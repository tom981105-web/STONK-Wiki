# STONK WIKI

가상 주식시장(**Market Battle**)의 **공식 백과사전 사이트**입니다.
플레이어가 회사 정보·시장 뉴스·IPO·업종 분석·랭킹을 한곳에서 확인합니다.
**읽기 전용**이며 Market Battle / Market Board 와 **동일한 Firebase 프로젝트**(`market-6e66a`)를 공유합니다.

> 순수 HTML + CSS + Vanilla JS. 빌드 도구·프레임워크 없음 → **GitHub Pages에 그대로 배포** 가능.

---

## 1. 핵심 설계 — 왜 "방 코드"인가

기존 프로젝트의 실제 Firebase 구조를 분석한 결과, **전역 `companies` / `news` / `ipos` / `marketEvents` 노드는 존재하지 않습니다.** 모든 실시간 데이터는 게임 방 단위로 저장됩니다.

```
rooms/{6자리코드}/
  ├─ status        "playing" | "ended" | ...
  ├─ marketTick
  ├─ stocks/{id}   { name, ticker?, sector, type, role, price, basePrice,
  │                  previousPrice, open, high, low, changeRate, volume,
  │                  value, volat, news, ... }
  ├─ latestNews    { text, time }
  ├─ ipo           { status:"subscribing", name, offerPrice, totalShares,
  │                  botDemand, applies{uid:qty}, startedAt, endsAt, stockId }
  ├─ players/{uid} { nickname, cash, holdings{id:qty}, connected }
  └─ logs / botFeed  체결 기록
```

또한 종목 이름은 **매 게임마다 랜덤 생성**됩니다. 따라서 안정적인 "회사 도감"의 기준 데이터는
`Market-Board/js/data.js`의 **정적 기업 카탈로그(40개사)** 가 담당합니다.

→ STONK WIKI는 **하이브리드** 구조를 채택했습니다.

| 모드 | 도감의 종목 목록 기준 | 동작 |
|------|------------------------|------|
| **카탈로그 모드** (방 미연결, 기본) | 번들된 `js/catalog.js` (40개사) | 방 없이도 도감·상세·업종·IPO 후보 완전 동작 (GitHub Pages 무설정) |
| **라이브 모드** (방 연결) | **그 방에서 실제 생성된 종목** (`rooms/{코드}/stocks`) | 방마다 이름이 달라도 그 방 종목을 그대로 표시 |

> ⚠️ **중요(설계 핵심):** 게임은 방을 만들 때마다 **랜덤한 이름**으로 종목을 생성합니다.
> 그래서 방에 연결하면 도감의 기준 목록 자체를 **"그 방의 실제 종목"으로 교체**합니다.
> (고정 카탈로그를 깔고 이름이 우연히 맞는 것만 값이 뜨는 방식이 아닙니다.)
>
> - 방 종목이 카탈로그에 **있으면** → 대표·설명·펀더멘털 등 프로필을 **병합**(`source: merged`)
> - 카탈로그에 **없으면** → 방 데이터(업종·타입·변동성·역할)로 종목코드·위험도·설명을 **결정적으로 생성**(`source: live`)
> - ETF·인버스·채권·우선주 등 특수 자산도 타입 라벨(업종)로 함께 표시
>
> 메인 화면에는 연결 시 **[이 방 종목 / 전체 도감]** 토글이 나타나, 원하면 전체 카탈로그도 볼 수 있습니다.
> 모든 결측 필드는 graceful 처리되어 화면이 깨지지 않습니다(요구사항 12).

## 3. 기능 구현 현황 (요구사항 1~15)

1. **메인 화면** — 로고/서브문구/메인 검색(회사·종목코드·업종·태그 통합) + 인기 태그 칩 ✅
2. **회사 도감** — 카탈로그 자동 생성 카드 그리드, 검색·업종필터·정렬(이름/등락/가격/위험/성장) ✅
3. **회사 상세** — `company.html?id=` 분리 URL, 모든 표시 항목 + graceful 결측 처리 ✅
4. **자동 투자 요약** — 업종·성장성·변동성·위험도 데이터 기반 문장 자동 생성 ✅
5. **회사 히스토리** — 실시간 뉴스 + 결정적 연혁(설립·상장·사업) 타임라인 ✅
6. **시장 뉴스** — 실시간 방 뉴스/급등락 이벤트, 상승/하락/중립 영향도 구분·필터 ✅
7. **IPO 센터** — 실시간 청약(진행중) + 도감 IPO/신규상장 후보 목록(상태 뱃지) ✅
8. **업종 분석** — 업종 카드(기업수·평균등락·변동성) + 업종 상세(거래대금 순위) ✅
9. **시장 랭킹** — 거래대금/상승률/하락률/거래량 TOP 20 (실시간) ✅
10. **즐겨찾기** — LocalStorage, 별(☆) 아이콘 토글, 전용 페이지 ✅
11. **반응형 UI** — PC/태블릿/모바일 (640·900px 브레이크포인트) ✅
12. **Firebase 구조 자동 대응** — 결측 필드 graceful, 미연결 시에도 무중단 ✅
13. **디자인** — 다크모드 기본, `#0f172a` 배경, `#22c55e`/`#3b82f6`/`#f59e0b` 포인트 ✅
14. **SEO·확장성** — 상세 URL 분리, 페이지 독립, `<title>`/`meta` 동적 설정 ✅
15. **사전 분석** — 기존 구조/Firebase/재사용 코드 분석 후 설계 (본 문서 1번 항목) ✅

> **시가총액 주의:** 방 데이터에 발행주식수가 없어 시가총액은 산출 불가합니다.
> 랭킹·업종 순위에서 **거래대금으로 대체**하고 화면에 명시했습니다.

## 4. 테스트 방법

### 로컬 실행
정적 파일이라 아무 정적 서버로 가능합니다. (`file://` 직접 열기는 일부 브라우저에서 Firebase SDK CORS 이슈가 있을 수 있어 서버 권장)

```powershell
cd "Market-Wiki"
npx http-server -p 5599 -c-1
# → http://localhost:5599
```

### 확인 시나리오
1. **방 없이(카탈로그 모드)**: 도감 40개 카드 표시, 카드는 "시세 — 방 연결 시 표시", 상세/업종/IPO 후보 정상.
2. **방 연결(라이브 모드)**: 우측 상단 **방 연결** → Market Battle 진행 중인 방 코드 6자리 입력 →
   - 헤더 칩이 `코드 · 진행 중`으로 변경
   - 도감 카드에 실시간 가격·등락률 표시, 메인 시장요약에 조스피 지수
   - 시장 뉴스/랭킹/IPO 청약 실시간 채워짐
3. **즐겨찾기**: 카드 별(☆) 클릭 → `favorites.html`에 누적, 새로고침 유지.
4. **검색**: "바이오", "NEKO", "#성장주", "한유진"(대표명) 등으로 통합 검색.
5. **반응형**: 브라우저 폭 축소(모바일) 시 레이아웃 재배치 확인.

### 배포 (GitHub Pages)
`Market-Wiki/` 내용을 레포 루트(또는 `/docs`)에 올리고 Pages 활성화하면 끝. 빌드 단계 없음.

> Firebase **Realtime Database 읽기 규칙**이 공개(`".read": true`)이거나 해당 방 읽기를 허용해야 라이브 모드가 동작합니다. (Board와 동일 조건)

## 3) Firebase 사용 데이터 (v1.1에서 읽는 항목)
모두 `rooms/{코드}` 하위, **읽기 전용**:
- `stocks/{id}.price` — 가격 기록 누적 → 미니차트 (관측값만, 랜덤 없음)
- `stocks/{id}.news`, `latestNews.text` — 뉴스 감성 분석 입력
- `players/{uid}.holdings` — 보유자 수·인기 순위·보유 주식 수(투자자 통계)
- `stocks/{id}.value`(거래대금) — 시장 점유율, 거래량 HOT, 시총 대체
- `stocks/{id}.changeRate` — Fear & Greed, 급등/급락 HOT
- (선택) `rooms/{코드}/priceHistory` — 있으면 차트에 우선 사용
> **발행주식수**는 방 데이터에 없어 "정보 없음"으로 안전 표시(시총은 거래대금 대체). **priceHistory 노드**도 현재 게임은 저장하지 않으므로, 연결 중 관측한 시세를 세션 동안 누적합니다.

- 방 **연결**: `rooms/{roomId}/stocks`가 기준, catalog는 보조. 우선순위 `stocks → latestNews → ipo → players → roomId 결정적 생성 → catalog fallback`. **catalog 고정 설명/위험도/강점이 방 종목을 덮어쓰지 못함**(검증 완료: 연결 시 dynamic=true로 override, 미연결 시 catalog 원본).

## 6) 동적 위험도 산식
base 30 + 변동성(min 35, |등락|×1.6) + 뉴스(부정 +14/긍정 −7) + IPO +14 + 보유편중(≥0.6) +10 + 데이터부족 +8 + 타입(채권/우선주 −30, 리츠 −14, 인버스 +20, 레버리지 +26, 원자재 +8) → clamp → **<32 낮음 / <56 보통 / <78 높음 / else 매우 높음**.

## 7) 동적 STONK SCORE 산식
5요소(0~100): 성장(업종+뉴스+가격흐름+시드) · 안정(변동성 역+데이터+타입) · 수급(보유자/시총점유/거래대금) · 모멘텀(등락×2.2+뉴스) · 리스크역(100−위험수치). **score = 0.25·성장 + 0.20·안정 + 0.20·수급 + 0.20·모멘텀 + 0.15·리스크역**, 0~100, 등급 SSS~D. 펀더멘탈 7지표는 5요소+시드로 도출.

## 8) 강점/약점 동적 기준
강점: 상승률≥5·긍정뉴스·보유자 견조·업종 내 상대강세·변동성대비 양호·IPO 관심·현금흐름·방어자산 / 약점: |등락|≥15·부정뉴스·보유집중≥0.6·데이터부족·급등추격위험·특수자산 방향성·리스크 매우높음. 데이터 전무 시 **"분석 데이터 부족"**.

## 9) 방 기준 투자 요약
업종 내 흐름 + score(등급/평가어) + 동적 위험도 + 뉴스 심리 + (고변동 주의) + **AI 의견** 문장 조합. 방마다 다름.

## 10) 공시 시스템
14종 템플릿(고정), 어떤 공시가 붙는지는 **roomId+종목 시드 + 조건(등락/업종/IPO)**으로 결정. 상장 공시는 `room.createdAt` 날짜, 나머지는 근거 timestamp 없으면 **"날짜 정보 없음"**(임의 날짜 생성 금지). 상세·히스토리·공시 섹션에 표시.

## 11) 관련 종목 추천 기준
방 연결 시 **`rooms/{roomId}/stocks` 내 종목만** 후보(검증: AI·전자 방에서 같은 업종 룸 종목만 추천, 카탈로그 기업 제외). 같은 업종·유사 위험도·유사 점수·가격 흐름 기준. 미연결 시 catalog 추천.
